### 与方案的偏差（需要你知道）

1. **P0-1 未把 `Department` 纳入 TenantMixin**：改为在路由和服务层按身份收口（效果等价、零迁移）。纳入 TenantMixin 需要改模型与平台超管跨租户读路径，留到 P1-5 与仓储写语义一起做。
2. **P0-4 未用 `on_duplicate_key_update`**：改为「批内去重 + 库内批量查重 + 失败逐条隔离」。保留 ORM 写路径，租户写入断言照常生效；多消费者并发的竞态由逐条隔离兜底，重放时会被查重跳过。
3. **P0-3 与 FR-73 冲突**：GWT-73.8 / 73.9 / 73.11 / 73.12（租户用自有模型行触发技能重评、同类建议）在 D32-A 下暂停。4 个用例标为 `xfail(strict=True)`：D32 选 B 放开后会因 XPASS 变红，届时移除标记；同时新增「租户带 BYOK 也 404 且零出站」用例。
4. **能力详情对租户不再下发 `file_path`**：GWT-14.2 的「相对库路径可保留」是可选项，公开投影不含库路径，比原口径更严，仍满足 14.2。
5. **npm 全量审计仍有 25 条**：全部在 react-scripts（CRA 已停维，所谓修复版本是 `react-scripts@0.0.0`）和 jest 构建链，不进浏览器 bundle。根治是迁 Vite（方案 R5 QA-11 的中期项）。

### BUG-43 时钟统一（本批最大一项）

**约定**（`platform_core/timeutil.py` 单一事实源）：库里存 UTC naive；MySQL 会话固定 `time_zone='+00:00'`；应用只用 `utcnow()`；业务日按 Asia/Shanghai 切；接口时间带 `+00:00`，前端按北京时间渲染。

| 层 | 处理 |
|---|---|
| 连接 | `DBManager` 同步 / 异步引擎、alembic、运维脚本、测试保真引擎统一 `init_command="SET time_zone = '+00:00'"` |
| 写入 | consumer 超时回收、调度 tick、告警静默窗、值班概览窗口改 `utcnow()`；cron 按北京时间解释再换算成 UTC（「0 9 * * *」= 北京 9 点）；支付宝请求时间显式北京时间；工人心跳 `started_at` 带偏移 |
| 读取 / 分桶 | 近 7 日任务数、结果数按上海业务日切（`business_date` 表达式，MySQL / SQLite 各自编译）；中转日用量改按业务日归属，与月度配额同一口径 |
| 接口 | 68 个 schema 时间字段改 `UTCDateTime`（出参带 `+00:00`、入参带偏移的换算成 UTC；OpenAPI 仍是 `date-time`）；dict 出参经 `jsonable_encoder` 同样带偏移；21 处手写 `isoformat()` 改 `utc_iso`；导出文件给人读，用北京时间 + `+08:00` |
| 前端 | shared 新增 `formatDateTime` / `formatDate`（北京时间，不看浏览器时区）；admin 22 处时间渲染统一接入（原先 6 列直接显示原始串） |
| 守门 | 静态扫描：应用代码出现宿主本地时钟即红；pydantic 模型出现裸 `datetime` 即红 |

**开发库换算**：`scripts/db/utc_backfill.py`（`inventory` 只读 / `apply --yes`，单事务，`system_configs` 记执行标记防重复减）。列按写入方分三类——库时钟 / 宿主本地时钟写的 61 列减 8 小时，Python 以 UTC 写的 12 列不动，`ON UPDATE` 列显式赋值防被刷成当前时间。换算后自检：`product_events` 的 `occurred_at` 与 `created_at` 平均差 **474.97 分钟 → 0**；订单创建 / 付款、令牌创建 / 最近使用、超管更新 / 最近登录等同一时刻写入的两列逐对相差 ≤1 秒。

## 测试提速（2026-09-30，用户反馈「pytest 运行极其耗时」）

方法：先量再改。`--durations` 全量分相位统计 + 单项计时 + cProfile；每改一处跑全量确认通过数不变。

| 发现 | 根因 | 处理 | 效果 |
|---|---|---|---|
| **每个用 DB 的用例都重建全部表**（主因） | 1150 / 2218 个用例各自对 SQLite 新库 `create_all` 59 张表，单次 0.1–0.2s；`sys` 时间 66s 也来自这里的文件 I/O | 会话级只建一次空库模板，各用例复制模板文件（0.6ms）；每个用例仍是独立的全新库，隔离不变；MySQL 保真通道仍逐测试建库建表 | 全量 219s → 96s，`sys` 66s → 10s |
