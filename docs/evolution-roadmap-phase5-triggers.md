## 5.1 进程分离 `run_worker.py`

**现状**：任务/结果双队列消费循环（`_dispatch_loop` / `_ingest_loop` / `_retry_loop`）
随 FastAPI lifespan 在 API 进程内启动（`backend/tasks/consumer.py` 运行模型注释、
`backend/app/__init__.py` lifespan 挂载）。API 进程与队列消费进程生命周期耦合。

**触发条件**（任一满足即启动）：
1. API 进程因消费循环内存/GC 抖动导致接口 P95 劣化（APM 或压测证据，需归因到消费侧）；
2. 需要 API 独立滚动重启或独立扩缩容，且队列消费不允许随之中断；
3. 消费者需独立多实例部署（须与 5.2 同期或先行完成）。

**验收标准**：
- [ ] 新增 `run_worker.py` 独立入口，可独立启停，`run_backend.py` 不再承载消费循环；
- [ ] API lifespan 中消费循环启动逻辑移除，API 停机/重启期间消息不丢失（Redis 队列残留可恢复）；
- [ ] 消费语义回归通过：优先级队列分发、失败重试退避（1s→5s→15s）、批量 ingest 计数一致；
- [ ] 优雅停机验证：worker 收到 SIGTERM 后在 blpop 超时周期内退出，不产生僵尸任务。

## 5.2 多实例语义：`_TOKEN_USAGE` Redis 化 + reconcile 互斥

**现状**：
- `_TOKEN_USAGE` 为进程级 dict（`backend/services/ai_planner/llm_client.py`），
  源码注释明示"单实例假设：多副本部署时预算无法跨进程聚合，需外部聚合方案"；
  多副本下跨请求 token 熔断预算会按实例数倍增失效。
- 启动对账 `reconcile_interrupted_plans` 在每个实例启动时无条件执行
  （`backend/app/__init__.py` lifespan），多实例同时重启会互相清理对方在途计划。

**触发条件**（满足即启动）：
- 部署实例数 ≥ 2（任一形态：docker replicas、多机多进程、同机多进程）。

**验收标准**：
- [ ] token 用量迁移 Redis 原子累计（INCRBY 语义），多实例总用量不超预算，熔断全局生效；
- [ ] `reconcile_interrupted_plans` 加分布式锁（如 `SET NX EX`），双实例并发启动仅一个执行对账；
- [ ] 单实例部署下行为与现状等价（Redis 不可用时的降级策略明确）；
- [ ] 存量单测（`backend/tests/test_llm_provider.py`、`test_backend_fixes_regression.py` 等
  对 `_TOKEN_USAGE` 的 patch 断言）回归通过，必要时同步更新 patch 面。

## 5.3 client 复用与探针并发化

**现状**：
- LLM client：provider 路径已有共享 `AsyncClient` 缓存（`get_shared_client`），
  兜底路径仍保持一次性 client（源码注释明示）；
- 渠道探针（`backend/services/channel_probe_service.py`）为串行逐渠道/逐问题执行，
  渠道规模增长时单轮巡检耗时线性放大。

**触发条件**（任一满足即启动）：
1. 渠道数量增长使单轮探针巡检超过调度窗口（经验阈值：渠道数 > 20 或单轮耗时 > 巡检间隔）；
2. 兜底路径调用量上升，连接建立开销可观测（压测数据或 APM 连接指标证据）。

**验收标准**：
- [ ] 兜底路径复用共享 client（或等效方案），不再每请求新建连接；
- [ ] 探针并发化（`asyncio.gather` + `Semaphore` 限流），单轮巡检总耗时有量化下降（记录前后对比）；
- [ ] 并发不破坏限流、超时与错误语义；探针结果与串行版本一致性抽检通过。

## 5.4 前端瘦身：React.lazy + 轮询门控

**现状**（`frontend/admin`）：
- 无路由级代码分割（源码中无 `React.lazy` 引用），antd/recharts 全量进首包；
- 多处 `setInterval` 常驻轮询且无页面可见性门控：
  节点页 15s、爬虫页 3s、日志抽屉/日志页 2s、AI 计划流程轮询；
  页面切走或标签页隐藏后轮询不暂停，浪费前端↔后端流量。

**触发条件**（任一满足即启动）：
1. admin 首包 JS 体积超阈值（建议判定线：gzip 后 > 1.5MB，以 `npm run build` 产物为准）；
2. 后台标签页轮询流量占比异常（Nginx/网关日志中可归因证据）；
3. 用户可感知的首屏加载或路由切换卡顿（体感反馈 + Performance 面板证据）。

**验收标准**：
- [ ] 路由级 `React.lazy` 分割生效，首包体积量化下降（记录构建产物前后对比）；
- [ ] `document.visibilityState` 隐藏时轮询暂停、恢复可见后继续（`visibilitychange` 门控），
  页面路由卸载时定时器清理无泄漏；
- [ ] 现有页面功能回归通过（含浏览器实证路径）。

## 5.5 多机文件状态对象存储

**现状**：文件管理（`backend/files/uploads|downloads|exports`、`storage/exports`）落本地盘，
storage 实现为 filesystem（`/api/v1/health/storage` 返回 `"filesystem"`）。
多机部署下上传/导出/下载文件仅存在于单一实例本地，跨实例不可访问。

**触发条件**（任一满足即启动）：
1. 部署实例数 ≥ 2 且文件接口需跨机可访问（上传与下载命中不同实例）；
2. 本地盘容量或 IO 成为瓶颈（容量告警或 IO 等待监控证据）。

**验收标准**：
- [ ] storage 层新增对象存储实现（S3/OSS/MinIO 任一），上传/导出/下载全链路走对象存储；
- [ ] 多实例读写一致；`/api/v1/health/storage` 如实反映实际后端类型；
- [ ] 保留 filesystem 实现作为单机/降级路径，配置切换可回退；
- [ ] 存量文件迁移方案明确（新文件走对象存储，旧文件可读或一次性迁移）。

## 启动流程约定

1. 达到任一项触发条件时，在本文档该项下追加"启动记录"（日期、证据、负责人）；
2. 实施完成后按对应验收标准逐条勾验，全部通过方可标记"✅ 完成"；
3. 多项同时达标时按 5.1 → 5.2 → 5.3 → 5.5 → 5.4 顺序启动
   （进程分离先行，前端瘦身最后，避免与其余项回归验证互相干扰）。
