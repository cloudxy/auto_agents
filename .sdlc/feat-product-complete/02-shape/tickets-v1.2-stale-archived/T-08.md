## 边界

**本票做什么**：扩 `llm_gateway/admin.py` Key 管理 HTTP（OpenAPI 核对 `/key/generate` 等价路径）。`issue_token`：网关成功后才 insert 本地行，写 `gateway_key_id`；失败不 insert。吊销：本地 `revoked_at` + 网关 HTTP 作废。明文一次。网关成功但本地 insert 失败 → HTTP 删除该虚拟 Key。

**本票不做什么**：

- 60.3 打通 / spend 回填 / QA-20 再打拒绝验收 → T-09（本票只保证「列表有则网关有」）
- GET 建组 → T-07
- 页上 Base URL → T-10
- 打开 `LLM.ENABLED` / 填上游 key / 焊根 compose
- 不改 `key_hash` 类型

**会改哪些文件**：

| 文件 | 改动性质 |
|---|---|
| `backend/services/llm_gateway/admin.py` | 修改：Key generate / delete HTTP |
| `backend/services/relay_service.py` | 修改：`issue_token` / 吊销（**若 T-07 未合，先只扩 admin.py**） |
| `platform_core/models/` relay_tokens ORM | 修改：ADD 两列映射 |

**不许改的文件**：根 `docker-compose.yml`（禁 litellm 服务）；任何 `LITELLM.DB_DSN`；`outbound_keys` 域。

## expand-contract

`relay_tokens.gateway_key_id` VARCHAR(191) NULL + `spend_synced_at` DATETIME NULL。UNIQUE 允许多 NULL。Step0：`SELECT gateway_key_id, COUNT(*) FROM relay_tokens WHERE gateway_key_id IS NOT NULL GROUP BY 1 HAVING COUNT(*)>1` 期望 0；有重复 → **停、问 pm**。禁止改 `key_hash`。禁止把骨架本地 sk- 回填成网关 id。

## GWT / Then（铺路，完整 60.3 在 T-09）

签发失败 Then（edge-states）：「签发失败：平台 LLM 网关不可达。没有产生令牌。」列表不得留下「有行、网关无」。明文只一次（GWT-60.1/60.11 半格）。**不得**把本地 `sk-` 201 当 60.3。
