## 边界

**本票做什么**：`GET /billing/orders` 本企业单、金额用户可见为 **元**、空态不是「暂无数据」。超管 `confirm` 不可逆 pending→paid；租户确认拒绝仍 pending。上报 `offline_order_submitted` / `offline_order_confirmed`（无明文、无支付通道密钥）。

**本票不做什么**：

- 写规则入口 → T-01（本票依赖它）
- 用量/订单 UI → T-03
- 上报失败不挡 / 租户查事件 404 → T-22
- **不得**把 `_apply_plan` 写成 GWT-50.10 通过条件，也不得单开票删除它（代选 Q-PRICE）

## GWT / Then（从 spec 抄）

- **GWT-50.3**：Then 看见该单：档位名称、状态=待确认收款、金额与定价页该档同一数字（用户看到的是元，不是要心算的「分」）；看不见其他企业的单。金额同数字 ≠ 已选「不撤 ¥299」。
- **GWT-50.4**：Then 看见「还没有升级申请。」以及去用量或定价的下一步；不是表格默认「暂无数据」；不是加载失败。（本票 API：200 + 0 行；空态句 UI 在 T-03。）
- **GWT-50.9**：Then 拒绝；申请仍待确认；配额不变。
- **GWT-50.10**：Then 申请变为已确认（不可逆，不得回到 pending）；租户下次打开「我的订单」看到已确认。是否把该企业配额履约为定价页专业档三数字 = Q-PRICE，本 GWT **不**验收履约。不得因确认把专业档写成「当前可买」。
- **GWT-50.11**：Then 申请保持已确认；不产生第二张单；不因第二次确认再叠一档配额副作用。
- **GWT-50.16**：Then 两张均为已确认（不可逆）；配额不因第二张确认再叠一档。第一张确认是否履约专业档三数字 = Q-PRICE，本 GWT 不验收履约。
- **GWT-92.1**：Then 上报 `offline_order_submitted`，含 `tenant_id`、档位名；超管查询面可查。
- **GWT-92.2**：Then 上报 `offline_order_confirmed`，含 `tenant_id`、档位名。
