# ADR-0023：能力资产统一导入通道——本地上传 + 沙箱解包 + 四类分发

> 状态：**accepted**
> 日期：2026-09-11｜决策者：architect 帽｜相关：spec v1.5 FR-100 / GWT-92.9；NFR-04（路径收容）；PC-2（不自动上架不动）；操作者 F11「必须要做到」

## 背景

现状只有 URL 导入（`backend/services/skill_import_service.py` 仅 `import_url`：raw/zip/GitHub 子目录）与服务器目录扫描；**无本地上传通道**，agents 无任何通道（spec §1.5 F11 file:line）。操作者要求：本地文件/目录一键导入 skill、agents、commands、plugins 四类。已有可复用原语：`_safe_member_path`（L60，路径规范化）与 `_write_to_library`（L242，目录行写入）。导入面是新的信任边界（浏览器上传任意文件进服务端），必须一次定死安全口径。

**触发这个决策的约束**：

| 约束 | 来源 |
|---|---|
| 四类齐（agent 通道补齐）；类型由导入过程判定 | GWT-100.4 |
| 目录导入部分成功，失败项列名称与中文原因 | GWT-100.2/100.3 |
| 超大文件拒绝含上限数字；同批其余继续 | GWT-100.5 |
| 路径逃逸条目拒绝；**资产目录外零新文件** | GWT-100.7；NFR-04 |
| 幂等重导不产生第二行 | GWT-100.8 |
| 导入未上架、不触发执行、公开商店不受影响 | FR-100 前言；PC-2 |
| 一次导入（含部分成功）上报 `asset_imported` | GWT-92.9 |
| 仅平台超管；租户无入口，直打 404 同形 | GWT-100.6；NFR-05 |

## 决策

1. **一个导入通道，四类是分支不是四个入口。** 统一上传 API（multipart：单文件 或 目录压缩包）→ 服务端**沙箱临时目录**解包 → 按各类型既有识别规则（frontmatter/清单）判定类型与名称 → 分发写入 capability library 目录行（**未上架**）。agents = 同一通道的新类型分支；URL 导入与服务器目录扫描保持，不废不移。
2. **沙箱收容（安全口径一次定死）：** 解包只发生在临时沙箱目录；每个条目路径规范化后必须仍落在沙箱内——`../`、绝对路径、符号链接条目**拒绝**并列失败原因（GWT-100.7）；写库/落盘目标限定资产目录，资产目录外**零新文件**。解包设大小上限（来自配置，NFR-10）与条目数/解包耗时上限，防压缩炸弹。
3. **部分成功是常态语义，不是错误路径：** 逐条结果（成功 → 类型+名称；失败 → 名称+中文原因）；0 可导入 = 中性说明「没有可导入的资产。」非静默成功非失败句（GWT-100.3）。
4. **幂等键 = 类型 + 名称：** 目录已有该行则本次跳过、不产生第二行（GWT-100.8）；不做版本合并/覆盖升级（那是 `check_update` 既有路径的事，不在本通道）。
5. **不自动上架、不触发执行：** 上架仍走治理台既有动作（PC-2 不动）；导入只产生目录行与一次 `asset_imported` 事件（origin= file/directory、types、succeeded、failed）。
6. **权限：** 导入动作仅平台超管（治理台=超管七叶，FR-37 保持）；租户无入口，直打与「页面不存在」同形（GWT-100.6）。

## 备选与否决理由

### 备选 A：四类各一个导入端点/入口

**否决理由：** 四套 UI、四套安全口径、四份逃逸防护——口径必漂。操作者心智是「把本地资产搬进来」，不是「选通道」。

### 备选 B：扩展 URL 导入，让用户先传 GitHub 再导入

**否决理由：** 操作者原话「必须要做到（本地直接进）」。强迫中转 GitHub 是把产品缺陷转嫁给用户；内网资产无 GitHub 可去。

### 备选 C：只扩服务器目录扫描到 agents，让用户拷文件到服务器

**否决理由：** 要求 shell 权限；操作者要的是产品能力。扫描通道保留但不承担本波 Then（GWT-100.1 的「选择文件」是浏览器动作）。

### 备选 D：上传即写入资产目录（跳过沙箱，边解析边写）

**否决理由：** 失败批次留下半写状态，回滚复杂；恶意条目在解析前就已触盘。沙箱先收容、验证后落位是唯一能兑现「资产目录外零新文件」的顺序。

## 证据

```
spike：导入现状与可复用面
问题：本地上传/agents 通道是否存在；路径安全原语是否已有
环境：读码 skill_import_service.py（import_url L74；_safe_member_path L60；
      _write_to_library L242；_ensure_no_conflict L220）；
      capability_service.py / plugin_service.py（目录行模型）
结果：无上传通道、agents 无通道；路径规范化与目录写入原语已在
结论：新建上传+沙箱通道，复用识别/写入原语；安全口径本 ADR 定死
```

未跑真实压缩包炸弹实验（属实现票测试面：T-35 验收注记含逃逸/超限夹具）。

## 代价与风险

| 代价 | 缓解 |
|---|---|
| 上传面扩大攻击面（恶意包/炸弹） | 沙箱 + 大小/条目数/耗时上限 + 不执行；深度病毒扫描本波不做（记 /sre 账本，§13 残留） |
| 大目录导入耗时长 | 异步/进度反馈（T-36 UX）；单批上限 |
| 类型误判（文件长得像两类） | 判定规则归一在通道内；失败项给中文原因，可改后重导（幂等兜底） |

## 影响范围

| 谁 | 需要做什么 |
|---|---|
| `/backend` | 上传 API + 沙箱解包 + 四类判定分发 + 逐条结果 + `asset_imported`；逃逸/超限夹具同 PR |
| `/dba` | 导入批次实体语义（contract §8）：明细可回放、幂等键=类型+名称 |
| `/frontend` | 导入入口 UX：文件/目录选择、进度、部分成功呈现（T-36） |
| `/sre` | 沙箱/上限配置项（配置即代码）；病毒扫描记账本 |
| `/qa` | GWT-100.1…100.8；逃逸条目后全仓扫描资产目录外零新文件 |

## 后续复审条件

若出现「导入后自动上架」「导入触发安装」类需求，重开本 ADR（那会碰 PC-2 与 FR-37 治理边界）。第三种导入来源（如 git clone）出现再评估通道抽象。
