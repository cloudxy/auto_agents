> 特征：`feat-product-complete`｜泳道：L4
> **本文件是 analyst 复盘的唯一口径。** spec §6 与本文冲突 **以本文为准**。
> 北极星继承 `feat-four-pillars-v2` 蓝图 v1.4 的 WACT。本特征 **禁止第二颗北极星**，禁止「任务∨订阅∨LLM」。

## 1. 判定纪律

| 项 | 规则 |
|---|---|
| 判定周期 | 本特征对用户可用之后 **4 个上海自然周**；中途不下成败 |
| 基线 | 无生产基线。第一轮目标 = 建立基线 + 护栏为 0 |
| 时区 | **Asia/Shanghai 业务日**；指标用 **事件发生时间** |
| 分流 | 无 A/B。分流单位若将来做实验 = **企业** |
| 排除 | 市场入站候选不得计入 WACT。测试种子企业 / `nfr01qc2-*` **不得**计入 D4 供给或「市场有货」。内部测试企业四周复盘用手工名单。**平台租户（slug=platform）的任务与事件不计入 WACT 与 PC-1…PC-4**（FR-102 后超管以平台租户入队属内部操作，不是市场租户价值；同走手工名单口径） |

| Q-VOICE | 未关前不得把核心动作改成订阅。改核心动作走变更流程，**禁止双北极星** |

## 2. 北极星（唯一，继承）

| 字段 | 内容 |
|---|---|
| 名称 | 周活跃完成租户数（WACT） |
| 口径 | 一个上海自然周内，至少发生 1 次 **核心动作** 的企业去重数 |
| 核心动作 | 采集任务进入 completed **且** result_count>0。排除 `is_marketplace_candidate=true` |
| 来源 | 事件 `task_completed`（已冻 FR-15：`tenant_id`、`result_count`、`spider`、`source`、布尔 `is_marketplace_candidate`） |
| 时间窗 | 上海周一 00:00 至周日 24:00，事件发生时间 |
| 目标值 | 建立基线。四周结束必须能报「这四周每周 WACT=？」；报不出 = 埋点失败。本特征不承诺 WACT 上升百分比 |

选「企业完成一次能交差的采集」，因为仍是离用户价值最近的动作。本波是收口 + 去堵点，不是改主叙事。

混淆：WACT=0 可能是没人来 / 注册后登不进（FR-83）/ **工人未运行**（FR-85）/ 满额出口打架（FR-50）/ 商店被种子吓走（FR-80）。用第 3 节驱动拆开，不得把工人空洞解释成「获客失败」。

## 3. 驱动指标（4 个，本特征）

v2 的 D1 注册成功、D2 168h 登录、D3 TTFV、D4 周订阅 **仍然有效**，口径不改。本特征 **追加** 下列 4 个，专门解释本波堵点。复盘时两套一起看。为避免与 v2 D1–D4 撞号，本表用 **PC-** 前缀。

### PC-1 注册邮箱登录成功率

| 字段 | 内容 |
|---|---|
| 口径 | 分子：该周注册成功企业中，注册时刻起 168h 内至少一次 `login_succeeded`、且登录标识为 **注册时管理员邮箱** 的去重企业。分母：该周 `tenant_signup_succeeded` 企业 |
| 来源 | 已冻 `tenant_signup_succeeded`、`login_succeeded`（FR-15）。若现事件无「用的是邮箱还是短名」，四周用抽检 10 次注册补；并在缺口表标 ⚠️ |
| 时间窗 | 每企从注册起滚动 168h；报表按上海周切片分母 |
| 目标 | 建基线。修好 FR-83 后，该率应从「用邮箱必失败」变为可观测成功——不设百分比 |
| 诊断 | 分母有、分子无 = 仍停在 FR-83 |

### PC-2 公开市场种子曝光

| 字段 | 内容 |
|---|---|
| 口径 | **护栏兼驱动。** 一周内公开市场列表或精选曝光中，测试种子出现次数。测试种子定义与 GWT-80.1 相同（短名 `nfr01qc2-*` / 标题「NFR卡片」/ 描述含 `preprod nfr-01 seed`）。**不是**「非种子列表打开率」，也没有「不含种子的打开次数 / 打开总次数」第二套分子 |
| 来源 | `market_list_viewed`（已冻 FR-43）+ `market_list_paged`（FR-92）。列表结果是否含种子：查询面抽样或列表项短名 |
| 时间窗 | 上海自然周，事件时间 |
| 目标 | 种子曝光 **0**。有翻页事件且 `result_count` 可报 = FR-81 可判定（翻页本身：页大小 ≤20，且当且仅当非种子 listed>20） |
| 诊断 | 列表打开>0 且种子出现次数>0 = FR-80 未完成。无下一页事件且非种子 listed>20 = FR-81 未完成 |

### PC-3 线下申请可自查

| 字段 | 内容 |
|---|---|
| 口径 | 分子：该周 `offline_order_submitted` 的企业中，能在「我的订单」看到至少一条本企业申请（抽检或后续查询面）。分母：该周提交申请的去重企业。**无**「随后 24h 内打开我的订单」窗口；spec §6 不得另写 24h |
| 来源 | FR-92 `offline_order_submitted` / `offline_order_confirmed`。**打开我的订单** 无事件 → 本指标 ⚠️ 不可全自动，用抽检 5 企 |
| 时间窗 | 上海周 |
| 目标 | 建基线。分母>0 且抽检看不到单 = FR-50 未完成。**完成停在「我的订单能看见已确认」**；确认后用量三数字 **不是**本指标完成条件（Q-PRICE） |
| 诊断 | 只看到超管待确认、租户看不到 = 闭环断在「我的订单」。缺「新上限」不得判 FR-50 未完成 |

### PC-4 渠道组令牌打通率

| 字段 | 内容 |
|---|---|
| 口径 | 分子：该周至少一次 `relay_token_call_succeeded` 的企业。分母：该周至少签发一把渠道组令牌的企业（签发可用抽检或后续若补事件；本波 FR-92 未冻签发事件，**签发分母 ⚠️ 抽检**） |
| 来源 | FR-92 `relay_token_call_succeeded`；用量数字 ≥1 可核对 |
| 时间窗 | 上海周 |
| 目标 | 建基线。分母有、分子 0 = 令牌仍是空壳（FR-60） |
| 诊断 | 有签发无成功调用：缺 Base URL / 未接到网关 / 网关不可达（后者走空态句，不计入「履约失败」当获客） |

v2 D2「168h 首次登录」与 PC-1 接近。PC-1 **额外**要求标识是注册邮箱。两者冲突时：D2 仍算「任意成功登录」；PC-1 专判 FR-83。不要把短名登录成功算进 PC-1 来假装邮箱断链已修。

**Wave A（v1.3）不新增驱动指标：** admin 总台面向操作者/超管，0 生产 UV，不设 PC-5、不改 WACT；判定走护栏（§4 追加行）+ 抽检/越权用例。`user_restored` / `asset_imported` 仅作可查事件，不进任何分子分母。

## 5. 埋点契约（本特征追加）

已冻事件（FR-15 / FR-43）不改名、不改字段最低集。查询面仍 **仅平台超管**；租户直打与「页面不存在」同形。

字段最低集：`occurred_at`、`anonymous_id` **或** 已登录的 `tenant_id`/`user_id`、`role`（若已登录）。失败不挡主路径。v1 至少一次。保留 ≥90 天。切日：存 UTC、报表日 Asia/Shanghai。**事件与日志不含明文钥匙、密码、平台网关钥匙。**

| 事件 | 何时 | 关键字段 | 对应 FR | 查询面 GWT |
|---|---|---|---|---|
| `offline_order_submitted` | 线下升级申请进入待确认 | `tenant_id`、档位名 | FR-92 | GWT-92.1 |
| `offline_order_confirmed` | 超管确认收款 | `tenant_id`、档位名 | FR-92 | GWT-92.2 |
| `outbound_key_issued` | 出站拉数钥匙明文展示一次 | `tenant_id`；**不含明文** | FR-92 | GWT-92.3 |
| `relay_token_call_succeeded` | 渠道组令牌对平台网关成功一次 | `tenant_id` | FR-92 | GWT-92.4 |
| `market_list_paged` | 公开市场点下一页且页面渲染 | `page`、`result_count`、`anonymous_id`（访客；无 `tenant_id`） | FR-92 | GWT-92.5 |

## 7. 漏斗（本波只补断点，不新造北极星漏斗）

### 注册 → 登录（PC-1）

步骤：`tenant_signup_succeeded` → 用 **注册邮箱** `login_succeeded`（168h）。无浏览会话的注册仍只进 v2 D1，不进 v2 F1 分母（v2 纪律不改）。

### 满额 → 申请 → 看见单（PC-3）

步骤：用量满额 → `offline_order_submitted` → 租户在「我的订单」看见 pending →（可选）`offline_order_confirmed` 后「我的订单」看见已确认。**FR-50 / PC-3 完成停在「我的订单能看见已确认」。** 用量三数字变为该档 = Q-PRICE，不是本漏斗、不是 FR-50 完成条件。缺「看见单」= FR-50 未完成；缺「新上限」**不得**判 FR-50 未完成。

### 签发令牌 → 打通（PC-4）

步骤：签发（抽检）→ 页上有 Base URL/用法 → `relay_token_call_succeeded`。无成功调用不得把 SKU 写成已履约。

### 市场（PC-2）

步骤：打开列表 → 种子出现次数（PC-2）必须为 0 → 若非种子 listed>20 则 `market_list_paged`。种子出现 = 护栏事故，不是「有供给」。
