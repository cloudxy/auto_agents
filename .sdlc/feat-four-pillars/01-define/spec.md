## 1. 背景与问题定义

四套 Working Backwards（每柱四句）。Sentence ③ 是用户能 **做** 的事。

### 1.1 柱 A · 智能采集

**谁**：租户里每天要把指定网页变成表格的运营/采集经办（operator），不是「会写爬虫的人」。

**现在什么情况**：官网说「粘贴链接交给 AI」；后台确有任务、AI 向导、结果与 CSV。但注册成功后没有登录出口；Worker 没启动时任务会一直等待且屏上不拦；官网还卖 Excel；数据中心导出最多 100 条且拒 xlsx。没有生产工单（ops：**0 张客户工单**），痛点来自对外承诺与可走完路径的对账。

**期望什么结果**：「我注册完能进后台，贴一个地址，最后拿到一份我打得开的结果文件；如果现在跑不起来，页面要告诉我卡在哪，而不是假装在爬。」

**凭什么说改善了**：注册后 7×24h 内出现首次 `task_completed` 且 `is_marketplace_candidate=false` 且 `result_count>0` 的租户比例可被计数（市场入站候选不构成首次出数；与第 6 节 WACT 核心动作、TTFV 同一口径）。本轮先建立基线。

### 1.2 柱 B · SaaS

**谁**：给公司开通空间的租户负责人（owner），以及被邀请进来的成员。

**现在什么情况**：免费注册、成员、用量三条进度条、运营台手改配额都在。定价页印着 ¥299、工单支持、渠道组、私有技能库；升级按钮却去再注册。月度 LLM 配额在套餐数字里，真正打模型的动作不走这道闸。没有付费用户样本、没有工单系统。

**期望什么结果**：「我知道自己买的是哪一档、用了多少、满了之后下一步点哪里；公司管理员不能因此拿到整座平台的渠道和模型开关。」

**凭什么说改善了**：配额拒绝可计数且带维度；注册→登录不再断链；定价卡上每条卖点都能被点通或被标成预告（基线先行）。

### 1.3 柱 C · 中转站（relay）

**谁**：平台值班（平台超管），在渠道额度炸了或模型变「像假的」时要判断能不能继续用。

**现在什么情况**：后台有渠道总览 / 探针 / 事件，远端不可达时有降级说明。官网零入口。企业档却写「中转站渠道组分配」。租户公司管理员与平台超管在写守卫上被当成同一类「admin」。是否独立卖、是否只是内部成本控制，**操作者未决**。

**期望什么结果**：「值班能看懂正品/伪装/不可用，能改窗口额度；公司管理员改不了全站渠道。租户侧看见什么，等产品定位拍板后再说——没拍板之前，定价不能假装已经卖这个。」

**凭什么说改善了**：非平台超管发起的渠道配置变更次数 = 0（护栏）；值班路径可走完（已有，Wave 0 收权限）。

### 1.4 柱 D · 能力市场（Power Market）

**谁**：三类人做三件不同的事（D10/D14/D21 已决，**不**合并成一种「用户」）：① 匿名访客逛目录；② 已登录租户给某个宿主订阅能力；③ 平台超管管源、上架、许可。宿主里的 Agent 使用者通过「安装说明」自己启用，平台不代改其本机配置（D21）。

**现在什么情况**：P6 目录能扫、能验证、技能广场能搜能打开正文；能力广场不能。没有上架态、没有订阅、没有预告、Kimi 清单会漏掉、公开能力列表丢掉「推荐」。设计已 Accepted。**无用户原声「我想安装」**——本柱进入冻结集是因为操作者已把 D10 定为一期必须，且现商店面零动作，市场不成立。

**期望什么结果**：「我搜 `code-review` 能找到；预告只能看不能订；已上架且过许可的，登录后能把同一能力订到 Grok/ZCode/Kimi/Claude 中的一个或多个宿主（每个宿主一行）；下架的商店里消失，但我已经订过的还能在『我的安装』里卸掉。」

**凭什么说改善了**：周去重「订阅成功」租户数可计数；公开列表不再出现未上架或许可黑名单项（护栏事故 = 0）。

### 1.6 RICE（只排序，不决定做不做）

ops：**0 张客户工单**、无访问日志、无付费样本。Reach **未量化**。下表 Reach 一律记 **1（占位：至少一个操作者/未知访客）**，**绝对值没有市场规模含义**，只用于波内相对排序。Confidence：**无埋点不得填 100%**。Effort：**pending architect**，区间为人周。

RICE = (Reach × Impact × Confidence) / Effort。Impact：3 巨大 / 2 高 / 1 中 / 0.5 低。分数差 <20% 不装精确，按依赖与「永不砍的安全」决定。

#### FR-01 对外承诺与当前可完成动作对齐

访客在官网首页、功能介绍、定价卡上读到的每一条「现在就能用」的能力，必须能在不离开产品的情况下走完；否则该条删除，或明确标「预告」且主按钮不得伪装成立即开通。

**Q-VOICE 未关闭前：** 不得新写并列四柱 Hero 承诺句；只允许删减空头、保留当前确实能演示的采集控制面描述。首屏那一句等操作者回答 Q-VOICE 后再填，不在本 FR 里选定「我们是爬虫 / 四柱平台 / 能力市场」。

|---|---|---|
| GWT-01.1 | 正常 | **Given** 某条定价或首页卖点对应的动作今天租户登录后能做完（例如免费档配额数字与用量页三条上限一致） **When** 访客阅读该卖点 **Then** 该卖点不以「预告」出现，且不链到无关出口 |
| GWT-01.2 | 空态 | **Given** 「工单支持 / 中转站渠道组分配 / 私有技能库」在当前产品里没有可走完的动作 **When** 访客打开定价页 **Then** 这三项要么不出现，要么带「预告」且主按钮不是「再注册一家企业」 |
| GWT-01.3 | 边界 | **Given** 租户成员（非平台超管）已登录 **When** 其打开官网定价/首页 **Then** 其看到的「当前可买」卖点集合与匿名访客相同；登录态不得多出仅内部才有的空头能力 |
| GWT-01.4 | 失败 | **Given** 首页技能精选或能力精选所依赖的公开列表当时不可用 **When** 访客打开首页 **Then** 该区块显示「技能列表加载失败」+ 主按钮「重试」，**禁止**把失败渲染成空白或「还没有技能」。首页其余静态区可继续显示 |
| GWT-01.5 | 越权 | **Given** 租户公司管理员已登录后台 **When** 其寻找「编辑官网卖点 / 改定价文案」 **Then** 没有该入口；官网文案保持平台发布面，租户改不了任何对外卖点 |

#### FR-14 公开发布物不含明文第三方密钥

公开发布树不得含可直接使用的第三方上游密钥。租户读面：渠道/中转页走 GWT-07.3（隐藏，直打同 404），该路径 **不渲染** 上游密钥。若租户仍能打开的系统设置上有密钥字段，只允许掩码，永不展示完整上游 Key。不以「打开渠道页并看到掩码」为验收。

### Wave 1 — 能力市场用户可见行为（冻结，D1–D29）

产品名对用户：**能力市场**（中文）。英文 Power Market 不作为导航名。  
商店五类平级（对用户 / API）：**技能 / 插件 / 命令 / 智能体 / 专家团**（`skill` / `plugin` / `command` / `agent` / `team`）。不再说「专家」。  
上架三态对用户：**未上架 / 已上架 / 预告**（D6）。**未上架 = 不展示、不能新订，不是停用**（D23）。  
治理态对用户：**实验 / 测试中 / 已发布 / 推荐 / 已弃用 / 黑名单**；公开只出「已发布」「推荐」。黑名单才是停用。  
订阅默认：启用=开，信任=关（D10）。**订/卸只作用于这一张卡**（D24）。  
宿主：`Grok` / `ZCode` / `Kimi` / `Claude`。  
`dev-team` **插件**对用户是「已合并，不可上架」（D20）；其子技能/命令/智能体不连坐（D25）。  
预告公开可见、不可订（D17）。  
第三方同步后不得变成已上架（D7）。  
词汇以 `CONTEXT.md` 为准。

#### FR-20 已登录租户把已上架能力订到一个宿主；预告不可订；重复订不新增

  实验 / 测试中 / 已发布 / 推荐 / 已弃用 / 黑名单
  公开允许：已发布 | 推荐

许可闸:
  默认黑名单不公开；超管放行后可公开（仍要过上架∩治理）

安装（租户 × 能力 × 宿主）:
  无记录 ──订阅成功──► 已订阅（启用=开，信任=关）
  已订阅 ──关启用──► 已订阅（启用=关）
  已订阅 ──确认开信任──► 已订阅（信任=开）  // 不写回能力行
  已订阅 ──确认卸载──► 无记录（可再订）
  已订阅(宿主 H1) ──订到另一宿主 H2──► 两行共存（各宿主一行；不覆盖 H1）
  预告/未上架/未过闸：订阅失败，保持无记录
  宿主名单未声明（NULL）：四个宿主都可订
  宿主名单已声明为空：订阅失败，保持无记录
