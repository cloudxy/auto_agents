## 0. 结论先行

这不是「缺四个功能」的产品问题，是 **对外已经在卖四柱、仓库只能演示碎片、权限与配额名实不符会泄漏** 的程序问题。

| 判据 | 结论 |
|---|---|
| 有没有真需求 | **有，但是程序需求，不是用户投票。** 客户工单 = 0，访谈 = 0，产品事件 = 0。能进 PRD 的证据只有：对外承诺 vs 仓库可证伪、Accepted 设计、角色诊断。 |
| 值不值得做 | **Wave 0 必须做**（诚实 + 收权 + 隔离），与 RICE 高低无关。Wave 1 是操作者已决的 D10，不是「用户强烈要求安装」。Wave 2/3 在开放问题关闭前不是可卖产品。 |
| 怎么知道有用 | 今天 **不能知道**。没有漏斗事件，Hero 数字是示意，仪表盘是任务计数器。本轮目标不是「提升 x%」，是「四周后能判定」。 |
| 8h 能不能做完四柱 | **不能。** 8h 只够诊断。四柱是多波程序（Wave 0 = 2–4 人周，Wave 1 = 8–16 人周，其后 pending architect）。 |

**一句话：** 先停止对访客说谎、停止让公司管理员当平台管理员；再按已冻结的 D1–D21 做出一个能订的「能力市场」；SaaS 可售卖环和中转站产品面，等操作者回答定价/账单/中转定位后再说。

## 1. 问题（用户能碰到的，不是系统缺模块）

每条都有来源。无来源的不写。Reach 一律 **未量化**。

### P1 访客第一次接触就会听到互相打架的「我们是谁」

| 面 | 自称 | 证据 |
|---|---|---|
| 官网 Slogan / Hero | 「AI 驱动的智能数据采集系统」；粘贴链接交给 AI | `SiteLayout.tsx` `SITE_SLOGAN`；`Home.tsx` Hero |
| 定价 | 成员、BYOK、工单支持、渠道组、私有技能库、¥299 | `Pricing.tsx` |
| README | 爬虫 + 大模型管理 + token 智能调度 + 官网与后台 | `README.md` 产品概览（**未列能力市场**） |
| 本程序 | 采集 + SaaS + 中转站 + Power Market | `state.yaml` |

导航只有：技能广场 / 能力广场 / 定价 / 注册。中转站、用量、能力市场一词都不在首页。

**用户后果：** 按采集来的人，定价页突然在卖渠道组；按「平台」来的人，首页只讲爬虫。Q-VOICE 未关之前，产品不能新写并列四柱 Hero——那是在继续说谎。

### P2 卖点有按钮，按钮带去的不是所卖的东西

| 承诺 | 实际可走完的动作 | 证据 |
|---|---|---|
| CSV / Excel 一键导出 | 任务导出拒 `xlsx`；数据中心最多 100 条 CSV | `FeaturesSection.tsx`；`test_export_bad_format_raises` |
| 128,000+ 任务 / 12 节点 / 3.2 亿条 | 静态示意，与后台 `/admin/stats` 不是同一数据源 | `Home.tsx` `HERO_STATS`；注释「纯静态展示」 |
| 专业档「联系升级」、企业档「联系销售」 | 三档 CTA 都进 `/register` | `Pricing.tsx` `href: '/register'` |
| 工单支持 / 中转站渠道组 / 私有技能库 | 仓库无工单模块、无渠道组、无私有技能库 | ops S-07 |
| 「注册成功，即可登录开始第一次采集」 | 成功页主按钮是「再注册一家」和「返回官网」，没有去登录 | `Register.tsx` |
| 「体验 AI 采集流程」 | `scrollIntoView('#ai-flow')`，不创建试用任务 | `Home.tsx` |

**用户后果：** 最贵的一步（开通企业）之后进不了产品。付费意向与免费注册是同一个出口，套餐意图不可分档。这不是文案润色，是激活漏斗在注册成功页断开。

### P3 两个广场，其中一个是空商场；失败还装成「没有货」

- 技能广场能搜、能打开正文、有 XSS 纯文本验收（`SkillsSquare.test.tsx`）。
- 能力广场四 Tab 卡片，无搜索、无详情、无订阅（`Capabilities.tsx`）。
- 首页技能精选：后端不可达时 `catch(() => setItems([]))`，看起来像「还没有技能」（`SkillsSection.tsx` L29）。
- 能力广场同样 catch 变空，Empty 文案是「暂无已发布…」（`Capabilities.tsx` L20–25）。
- 公开技能列表含 `recommended`；公开能力列表只 `stable`——两套测试分别钉死（`test_skill_public_api.py` vs `test_public_capabilities_only_stable`）。

**用户后果：** 逛店的人不知道进哪扇门；店挂了会以为平台没货。D19 已决「只留能力市场」，但那是 Wave 1，不能拿来原谅 Wave 0 首页继续失败装空。

### P4 公司管理员能做平台管理员的事

租户 `admin` 与平台超管在写守卫上被当成同一类：可扫目录、拉验证、进中转站改窗口、改平台 LLM（architect V2/V3；backend；qa）。资产是平台目录（`tenant_id` 恒 NULL），却用 `require_admin` 而不是「仅平台超管」。

**用户后果：** 给公司开通空间的人，可以动整站渠道和目录。这不是「功能还没做」，是 **泄漏**。权限、安全、一致性不参与 appetite 裁剪。

### P5 用量页上的数字，不是用户以为的那道闸

- 套餐写「20 万 tokens」，真正打模型的规划/试采不走这道闸（backend）。
- 定时 / 模板 / AI 试采入队会丢租户（backend §8）。
- 市场入站候选写在采集结果表里，可能顶满企业存储（data-collector；analyst Q4）。
- 超限抛 `QUOTA_EXCEEDED`；用量页 Alert 把这个内部码展示给用户（`Usage.tsx` L45）。进度条在 ≥90% 变红（L59），没有「下一步」主按钮（支付也不存在）。
- 出站拉数是平台级 `X-API-Key`，按爬虫名查、无租户维度（`public.py` `query_public_results`）。名单空 = 全部拒绝（有测试）；名单一旦有 key，隔离不在这条路上。

**用户后果：** 「我们公司用了多少」不可信；满了不知道去哪；别人的结果有可能被平台钥匙拖走。T-06 租户自助 Key 是下一轮，不能当成本轮对隔离的 waiver。

### P6 「能力市场」在设计里已经成立，在用户面前还不存在

D1–D21 Accepted，评审 0 open。商店面零订阅动作。无用户原声「我想安装」——ops S-15 写明不要编成用户强烈要求。本机 6 插件 / Kimi 16 包是操作者磁盘盘点，不是市场规模。

**用户后果：** 若按设计对外讲「能订到 Grok/ZCode/Kimi/Claude」，今天是空头。Wave 1 冻结的是用户可见行为（逛、搜、预告、订、卸、上架闸），不是开发者门户、分成、代写本机配置。

### P7 中转站是产品柱还是内部成本控制，用户侧互相否定

README 把它列为第三模块；官网零入口；默认 `NEWAPI.ENABLED=false`；企业档却写「中转站渠道组分配」。探针伪装不自动下线渠道（今日行为）。是否独立卖 = Q-RELAY，本帽不选。

**用户后果：** Wave 0 只能删空头、收写权；不能新造「我的渠道组」。未拍板之前把中转写成当前可买 = 继续 P2。

### P8 做完也无法证明做对了

无 `metrics.yaml`，无产品事件 SDK，登录不落事实，导出无审计，配额拒绝不计数（analyst Q8–Q12）。Dashboard 成功率是全历史，近 7 日结果是另一窗口，LLM 月用量用 UTC（FR-16 要收口）。Hero 数字不能当基线。

**用户后果：** 对操作者——四周后无法回答「注册后有没有人进得去、出得了数、订过能力」。对访客——无影响，直到我们用假数字代替度量。

## 2. 为什么会这样（产品原因，不是实现清单）

### W1 先写了「我们是平台」，再补「谁能走完」

四柱是程序目标，官网是采集获客页，定价是示意 SaaS，README 是模块目录。三份材料各自正确、拼在一起是假产品。根因是 **用解法清单代替问题定义**：没有四句 Working Backwards，就把能力市场、中转站、套餐写上墙。

### W2 证据真空被当成「没有问题」

0 张客户工单 ≠ 0 个用户问题。没有工单系统的产品，投诉通道本身就是定价空头（S-07）。没有埋点，就不能用「没人叫」为 Hero 大数、双广场、注册断链辩护。

### W3 把「已有页面」当成「已有产品」

采集控制台、成员、用量三条杠、渠道总览、技能广场搜索——这些是 **已有能力**（T-26/T-27），不是四柱可卖。P6 目录能扫能验证，不等于市场（上架 ≠ 信任 ≠ 启用 ≠ 订阅）。中转值班页存在，不等于租户产品。

### W4 角色词没分开

「admin」同时指租户公司管理员和平台超管。产品矩阵若写「管理员能改渠道」，实现就会让租户 admin 过 `require_admin`。市场写面 D14 已决仅平台超管；中转/LLM 若本波不一起收，就会「市场严、中转松」。

### W5 度量被留到「上线后再说」

没有事件的北极星是空话。把埋点写成技术任务，上线后查询面没有字段（候选标记、登录失败、spider/source），WACT「排除市场入站」会无法落地——这是 QA-02 能成为 blocker 的原因。

### W6 操作者已决 ≠ 用户已要

D10 一期做租户安装，是战略冻结，Confidence 50%。把它写成「用户强烈要求安装按钮」会污染分诊，并在无门户、无分成时问出错误的获客故事（那是 Q-MARKET-USER，不在本帽代选）。

### W7 安全例外没写进范围，就会在实现里变成后门

平台出站 Key、明文上游 Key 被 git 跟踪、候选占配额——若只在诊断里出现、不进 FR 或范围外，Wave 0「永不砍隔离」就是口号。已知洞必须变成产品规则：拒绝、绑定到企业、或显式列入范围外并承认它与隔离红线冲突。本诊断选择：**无租户绑定的出站拉数 = 拒绝**，不把跨租户拖库写成可接受的平台后门。

## 3. 改进（产品切片，不是方案）

### 3.1 程序切波（已写入 spec §0）

| 波 | 用户能多做到什么 | 永不砍 |
|---|---|---|
| Wave 0 | 访客不被空头和假数字说服；注册完能去登录；公司管理员改不了平台目录/渠道/模型；配额和任务算在自己公司；失败不当空 | 安全、权限、隔离、配额执法、公开不泄露 |
| Wave 1 | 一个「能力市场」：短名可搜、预告不可订、已上架可订到指定宿主、超管决定上架与许可 | listed ≠ trusted ≠ enabled ≠ 已订阅；许可闸；越权审计 |
| Wave 2 | 用量页看得出免费档，满额下一步不是再注册（支付本身 = Q-BILL） | 不偷改成在线扣款 |
| Wave 3 | 中转对租户可见性随 Q-RELAY；未拍板不新造渠道组屏 | 写权已在 Wave 0 |
| Wave 4 | 一条链接到可导出结果；无工人时被拦住 | 不承诺任意站点、登录墙、xlsx、准确率 |

超出单波 appetite 50% → 停下重判，不是自动延期。禁止一张「实现四支柱」巨票。

### 3.2 分诊纪律（本程序）

- **真问题先进 Wave 0：** 叙事裂缝、激活断链、权限泄漏、配额名实、密钥、不可测。
- **战略已决进 Wave 1：** D1–D21 用户可见行为。禁止只上目录不上闸。
- **伪需求 / 无原声：** 站点模板商店、开发者门户、分成、官方认证、代写 `~/.zcode`、coming_soon「通知我」。
- **已有能力：** 采集任务/AI/成员/用量/值班页/技能搜索与 XSS 纯文本——保留并迁，禁止直接删光。
- **一次性：** 本机插件盘点只用来定身份规则，不当 Reach。

### 3.3 度量（本轮成功 = 能判定）

北极星唯一：周活跃完成租户数（WACT）= 自然周内 ≥1 次「采集完成且条数>0」的企业去重，**排除**市场入站候选。若 Q-VOICE 改为能力市场优先，用变更流程换核心动作——禁止两个北极星。

驱动：注册数、注册后 168h 登录率、TTFV、周订阅成功租户数。护栏：跨租户可见 = 0；公开泄漏未上架/黑名单/未放行许可 = 0；任务失败率相对基线 +10pp；非超管改渠道/平台 LLM = 0；配额拒绝不可理解 = 0；失败装空抽检 = 0。

缺的事件写成 FR-15 / FR-30，与功能同期验收。无基线 → 目标就是建立基线。判定周期：相关波次对用户可用后 4 个上海自然周。

### 3.4 本帽明确不选的

| 问题 | 为什么不选 |
|---|---|
| Q-VOICE 对外第一句 | 操作者定位；选了就会写死 Hero 和北极星核心动作 |
| Q-PRICE 空头撤 vs 履约 | 操作者商业；Wave 0 只冻「未履约不得写成当前可买」 |
| Q-RELAY 中转 SKU | 操作者；Wave 0 只冻写权 + 租户默认不能打开渠道页 |
| Q-MARKET-USER 市场主用户 | 不重开 D10/D14/D21 |
| Q-BILL 在线账单 vs 联系销售 | Wave 2 支付 FR 的开关 |
| Q-LLM LiteLLM vs new-api | 技术数据面，交给方案帽材料，产品不选 |
| Q-AGPL | **必须出现在操作者必答表**（审查 QA-08）：Q-RELAY 一旦变成对外收费，先关 AGPL 故事再写可买。本帽仍不代选答案 |

后台 IA 重组（中转升组、幽灵 `/enterprise` `/rbac`、日志三处）**本程序不改菜单分组**——那是设计师 P0，但本波 appetite 不够，且不阻塞诚实与收权。列入范围外，避免「顺手改信息架构」。
