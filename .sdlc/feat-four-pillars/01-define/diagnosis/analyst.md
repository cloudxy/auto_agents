## 4. 分析

### 4.0 埋点：蓝图事件 vs 仓库

字段最低集（蓝图）：`occurred_at`、`anonymous_id` **或** 已登录的 `tenant_id`/`user_id`、`role`。  
检索：`official_page_viewed` / `market_subscribe_succeeded` 等产品事件名在 `*.py/ts/tsx` **仅**命中通知类型字符串，不是分析事件。前端无 posthog / mixpanel / amplitude / gtag / analytics SDK。`02-shape` 曾写 `product_events` 表，`state.yaml` 标 **stale**，代码零落地。

| 事件（蓝图冻结名） | 何时 | 今日落点 | 判定 |
|---|---|---|---|
| `official_page_viewed` | 首页/定价/市场/注册 | 无 | 洞 |
| `official_cta_clicked` | 主按钮，`cta` 五档不得合并 | 无；定价三档同 `/register`；首页主按钮不在五档内 | 洞 |
| `tenant_signup_succeeded` | 企业开通 | `tenants` 行 + `logger.info`；无审计、无事件 | 行可数，事件不可查 |
| `login_succeeded` / `login_failed` | 登录结果；成功须带 `tenant_id`；失败原因分类不含密码 | JWT 响应有 `tenant_id`；`users` 无 last_login；失败 Redis 计数易失 | 洞 |
| `task_run_submitted` | 提交采集 | 审计 `task.run` / `task.run_from_template`（写操作，无读分母） | 审计 ≠ 事件 |

### 4.1 北极星可行性（WACT）

蓝图：一周内至少一次「采集完成且条数>0」的企业去重；排除市场入站；目标 = 四周结束能报出每周 WACT=？；报不出 = 埋点 FR 失败。

**问题 1 — 验收对象不存在。** 没有事件、没有按 `event_name + occurred_at` 的查询面。任务表重构违反「验收以事件可查为准」。

**问题 2 — GWT 与蓝图字段不一致。** `spec.md` GWT-15.1 列出的 `task_completed` 字段是时间、租户/用户、`result_count`，没有「是否候选 / spider·source」。蓝图 §5 和北极星排除条款需要这些字段。按 GWT 变绿 ≠ 能算 WACT。

**问题 3 — 排除规则今日未接线。** 候选在结果行 `source=marketplace`、任务行常见 `spider_name=skill_harvester`。统计 API 不过滤。平台超管看全库时，入站任务会进「完成」。

**问题 4 — 时区。** 蓝图要上海自然周、事件发生时间。完成时刻在 `completed_at`（tz-aware），stats 切日用 `datetime.now()`。没有 Shanghai 转换。周界会错。

**问题 5 — 混淆。** README / 仪表盘路径：Worker 未启动则任务一直 pending。WACT=0 可能是「没人来」「来了没登录」「登录了跑不起来」。蓝图驱动指标能拆获客/登录/出数，但必须三件都可查；今日后两件是洞。`slug='platform'` 若被拿来试跑，会污染企业去重。

**问题 6 — Q-VOICE。** 核心动作允许改成「订阅成功」，禁止双北极星。观察钟在叙事未冻时启动，四周数字不可比。

**改进：** ① 事件查询面按上海周切 `occurred_at`，WACT SQL 只打事件表。② `task_completed` 带 `is_marketplace_candidate`（或 source/spider），GWT 与蓝图对齐。③ 四周备忘排除 `platform` + 操作者提供的测试企。④ WACT=0 时先看 D1/D2，再看节点是否在线——**这是诊断顺序，不是因果断言**。⑤ Q-VOICE 关闭前不要宣称「第一轮观察已开始」。

任务表核对（**非正式**，禁止复制进口径）：

```sql
-- 核对用：上海周 × 企业去重的「完成且有条数」任务。
-- 不是 WACT。缺事件、缺候选标记、会话时区未知。
-- 假设 completed_at 存 UTC；若实际是 naive 本地，CONVERT_TZ 会错。
SELECT
  YEARWEEK(CONVERT_TZ(completed_at, '+00:00', '+08:00'), 1) AS iso_week_mon,
  COUNT(DISTINCT tenant_id) AS oltp_proxy_not_wact
FROM spider_tasks
WHERE deleted_at IS NULL
  AND status = 'completed'
  AND COALESCE(result_count, 0) > 0
  AND spider_name <> 'skill_harvester'
GROUP BY 1
ORDER BY 1;
```

候选污染检查：

```sql
SELECT COALESCE(source, '(null)') AS source, COUNT(*) AS n
FROM spider_results
WHERE deleted_at IS NULL
GROUP BY COALESCE(source, '(null)');
```

**问题 — 身份拼接。** 蓝图字段是 `anonymous_id` **或** `tenant_id`（或）。F1 按企业去重。曝光发生在注册前，只有匿名 ID。`tenant_signup_succeeded` 若不准入同一 `anonymous_id`，步 1–3 无法按企业连成漏斗，只能报互不相关的事件计数。计数 ≠ 漏斗。

**问题 — 双入口。** Hero「进入管理后台」正是蓝图要从 F1 拿掉的那条路。必须另报「后台直达」序列，否则修好注册页之后，登录成功会看起来像从官网漏斗来的（选择偏差 + 入口污染）。

**问题 — CTA 枚举盖不住 UI。** 五档没有 `enter_admin` / 页内锚点。不补枚举又不分报，四周 CTA 表是空的。

**改进：** 注册成功事件携带注册前 `anonymous_id`（cookie 贯穿）。官网漏斗与后台直达 **两张表**。CTA 枚举要么扩到真实主按钮，要么首页主按钮改走蓝图已有档——产品选择交给 pm，analyst 只标：现状两边都不覆盖。D2 在 FR-04 登录出口落地前，分子≈0 解释为路径断裂。

### 4.3 漏斗 F3 · 市场浏览 → 订阅

设计文档步骤：公开列表（listed ∪ coming_soon）→ 搜索 → 详情（name 或 alias）→ 登录 → `POST /tenants/me/installs`（仅 listed）→ enabled/trusted。安装表是 **存量状态**，不是浏览事件。

蓝图 F3：`list_viewed` → search（可选）→ `detail_viewed` → `subscribe_succeeded`。预告拒绝进 `rejected`。Wave 1 前全部不可测。

| 步骤 | 今日观测 |
|---|---|
| 全部 | 无表、无 API、无前端动作、无事件。卡片不可点穿 |

把今日广场请求当市场入口会高估「市场」——那是目录陈列。`coming_soon` 可见不可订（D17）：列表 UV 含预告，订阅分母若用 list_viewed 会系统性偏低，**必须**按详情上架态切片，或订阅漏斗分母改用「详情且 listed」。蓝图未写这一刀。

**未冻：** F3 步间时间窗；search 可选时 list→detail 是否允许跳过 search（文案写了可选，步骤规则表没写允许跳步）。不定清楚，两个人算出的 F3 会不一样。

### 4.7 无 A/B 面

实验六项：无预注册假设、无 assignment、无 MDE、无停止规则、无实验平台。`POWER_MARKET.ENABLED`（设计，代码未落地）是总开关，不是 50/50。权限码和 Dynaconf 是发布控制。

蓝图：无 A/B 面；若将来做，分流单位 = **企业**。SaaS / 市场有交互效应，按用户分流会让同企看见不同目录。同意，不改。

n 未知。技能要求算不清样本量就放弃实验，改灰度 + 定性。**本轮四周判定本来就不是实验**（蓝图：中途不下成败；analyst 只描述变化）。

### 4.8 审计 ≠ 产品事件

`record_audit` 覆盖任务/定义/调度/模板/告警、AI 计划、LLM、成员、RBAC、租户 CRUD、技能扫描/候选/评分、插件 verify、渠道、通知、死信。

它不是分析事件流：

- 只写高危写，不写读（列表/详情/搜索/Dashboard）
- 不写登录、导出、配额拒绝、公开页浏览
- 无 `anonymous_id`
- `operation_logs` 在租户豁免表，按 actor 不按 tenant
- `record_audit_standalone` 失败吞掉 → 分析会少计失败操作

**决策规则：** `COUNT(operation_logs WHERE action='task.run')` 不得当采集使用率——打开过任务页的分母不存在。

### 4.9 设计文档对 F3 的含义（非运行态）

`power-market-design.md` 的 Q10/Q11 是「我的安装」列表与一行 upsert，支撑的是 **存量安装行**，不是 browse/search/click。D10 做 `capability_installs` 之后，仍然数不出「看了没订」。蓝图 FR-30 正是补这块；实现时不要把安装表当作漏斗完成。

### 修正后的结论
