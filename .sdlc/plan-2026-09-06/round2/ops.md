## 0. 结论先行

1. **法务与发版是「发不了」级缺口**：全仓（根目录/docs/pyproject/官网页脚）无 LICENSE、无服务条款、无隐私政策（§1.1）；发版说明模板在 ops skill 里要求具体，但全仓零次实际使用（§1.3）。
2. **四个北极星指标只有「半个能算」**：爬虫「任务完成」可从 spider_tasks 算出，但「交付」无埋点；SaaS 付费、中转站虚拟 Key、资源库使用三项目前结构性不可能（§2）。
3. **竞品定价给出的走廊很窄**：中转站对标的 Portkey 免费档就给 Virtual Keys+预算，¥299/月必须用「治理/探针/中文服务」差异化而非网关功能本身（§3）。
4. **对外叙事三处口径打架**：README 说中转站是「new-api 外挂巡检器」、定价页把「中转站渠道组分配」卖给企业档、pm 报告说它是可售卖板块——而 `NEWAPI.ENABLED: false`，从未运行（§1.2）。

### 1.3 发版说明机制：模板强、实践零

- **模板存在且要求明确**：ops skill `templates/release-notes.md` 规定用户视角语言、可感知数字、逐条修复、破坏性变更给迁移期、诚实列已知问题，并附写作检查清单与常见错误对照。
- **实际用法为零**：全仓 find `*release*/*changelog*` 零命中（排除 node_modules）；docs/.sdlc/.scratch grep release note/发版说明/CHANGELOG 零命中。docs/ops/ 仅有 `deploy.md` 与一封事故复盘 `incident-2026-08-backend-freeze.md`。
- **判定**：机制是「纸面就绪、从未运转」。LiteLLM L1 影子接入（bf8db62/3ce0548）这类用户可感知的节点都没有发过任何通告——若 L2/L5 切流时才第一次写发版说明，恰逢引擎更换的最大沟通风险点。

## 2. 北极星可观测性：四板块「成功的第一信号」现在能不能算

> 口径：每板站一个「成功的第一信号」，逐个对照现有表/埋点判 **能 / 部分 / 不能 / 缺埋点**。当前无外部用户，所有指标值均为 0——本节判的是「上线后第一天起能不能算出来」，不是「值是多少」。

| 板块 | 北极星（第一信号） | 判定 | 现有依据 | 缺口 |
|---|---|---|---|---|
| **爬虫** | 首个任务成功交付数据（租户维度） | **部分能** | `spider_tasks` 带 TenantMixin + status(completed/failed) + result_count + completed_at（`spider_task.py:25,30,40,46`）→「完成且有产出」可算；task_completed 站内通知已有（`notification.py` docstring） | **「交付」语义缺埋点**：结果导出 `GET /results/{task_id}/export` 无审计（`spiders/results.py:81-89` 仅 delete 有 `record_audit` :64）；「下载/查看次数」不可知。运营口径可先用「completed 且 result_count>0」替代，但与「客户真正拿到数据」有偏差（沉默流失正好发生在这里，signal-quality.md：行为数据是发现沉默需求的唯一手段） |
| **SaaS** | 首个付费/活跃团队 | 付费：**不能**；活跃：**部分能** | 付费：全仓无 plans/orders/subscriptions 表（pm.md §1.2 已证）——结构性不可能。活跃：`spider_tasks`/`llm_token_usage`/`notifications` 均带 tenant_id（`llm_token_usage.py:9` TenantMixin），可按租户算「当日有无任务/有无调用」 | 用户表无 last_login/last_active（`user.py` grep 零命中）；`operation_logs` 无 tenant 列（`operation_log.py:11-17`）需 join users 才能到租户，且它是高危操作审计、不是行为埋点——「登录了但什么都没做」的租户不可见 |
| **中转站** | 虚拟 Key 首次调用成功 | **缺埋点**（前置能力不存在） | platform_core/models 与 alembic/versions grep virtual/litellm **零命中**——L3 未建，Key 本身不存在。`channel_events` 只记录渠道启停且无 tenant 维度（`channel_event.py:26` channel_id 为 new-api 外部主键）；`llm_token_usage` 是**内部直连路径**（llm_client→llm_usage_service）的记账，不是中转转发路径 | L3 落地时 spend 在 LiteLLM 自有 Postgres——「首次调用成功」必须设计成双源可算：本仓建 virtual_keys 表（发放时刻）+ 对账任务回填 spend。**建议把「注册即得 key→首次 200 响应→写一条 first_call 事件」写进 L3 验收**（pm.md §5 第 4 条 GWT 已有雏形，补观测点） |
| **资源库** | 技能被外部用户真实使用 | **缺埋点** | `skills` 表无 download/view/install 任何计数字段（`skill.py:23-53` 全字段核对）；`public_skills.py` 唯一计数是**限流** Redis incr（:81-84），语义是「防刷」不是「使用」 | 最小补法：公开端点加一次 Redis incr（view）+ 导出/安装动作写 operation_log（target=skill#name）——两周内可做，不改 schema |

**汇总**：能算的只有爬虫「任务完成」（半格）。这意味着如果 4 周后接种子用户，**上线首日我们甚至无法回答「谁来了、做了什么、拿到没有」**——埋点补齐应先于或同步于首批用户进入，而不是事后补。

## 3. 竞品三层（2026-09-06 在线抓取，每个给借鉴/回避/差异化）

> 抓取方式：curl 直取官方页面/GitHub raw 当日文本。频次口径：均为官方一手页面，非转述。

### 3.1 LLM 网关（LiteLLM 迁移决策的竞品语境）

| 对手 | 2026-09 现状（带出处） | 层 | 借鉴 / 回避 / 差异化 |
|---|---|---|---|
| **LiteLLM** | 开源自托管 AI Gateway，100+ LLM，「virtual keys, spend tracking, guardrails, load balancing, admin dashboard out of the box」；企业档另售 | 直接（迁移目标即它） | **借鉴**：虚拟 Key+预算+spend 是「开箱」能力，L3 不要自研重造。**回避**：不做通用网关平台（不与 proxy 本体竞争）。**差异化**：真伪探针 10 维指纹 LiteLLM 无对位（product-review.md:142），叠加「租户级中文账单/通知」 |
| **new-api** | Token 分组/模型限制/用户管理 + 缓存计费统计 + key quota 查询工具（new-api-key-tool）；README 明确要求用户「合法取得上游 key、遵守上游 ToS」 | 直接（现引擎+生态） | **借鉴**：其计费模型（quota/倍率）是国内中转站事实标准，定价页口径应对齐它的用户习惯。**回避**：不复制其「上游 ToS 合规风险」——自营渠道组需留上游授权凭证。**差异化**：渠道真伪/套壳识别 |
| **OpenRouter** | 透传底层 provider 定价 + 统一 API + fallbacks + analytics/workspaces/budgets/SSO（FAQ 原文「passes through the pricing of the underlying providers」） | 间接（云托管龙头，非自托管客群） | **借鉴**：「价格=原价」透明策略与统一账单体验是用户预期基线。**回避**：不打价格战——透传模式下无价差可让。**差异化**：国内直连可用性 + 发票/对公 |
| **Portkey** | Developer 免费档即含 10k logs/月+网关+Virtual Keys（预算支持），Production **$49/月**（100k logs、RBAC），Enterprise 定制（SOC2/HIPAA/VPC/SSO）；站内已宣告升级为「PRISMA AIRS AI Gateway」企业安全方向 | 直接（最接近的 SaaS 化对手） | **借鉴**：免费档给全功能小额度、付费档按「日志量+合规」分层的阶梯。**回避**：不追 SOC2/HIPAA 合规军备赛（内网阶段无此预算）。**差异化**：**¥299/月 恰落在 Portkey $49（约 ¥350）之下**——中转站卖点是「比 Portkey 便宜 + 中文 + 探针治理」，但必须先有 L3 才成立 |

## 4. GTM 最小动作：假设 4 周后接 5 个种子用户

> 分级口径：**P0 = 没有就发不了（发版阻塞项）**；**P1 = 没有就留不住/卖不动**；**P2 = 有更好**。全部为非代码资产（文档/法务/流程/渠道），代码缺口归 pm.md Top-8，不重复。
