## 1. 背景与问题定义

**谁**：要把网页变成本企业表格的 **采集经办**（角色 operator）；要「能买能付」的 **买方（公司管理员 / 开通负责人）**；要守住平台写面的 **平台超管**。不是「用户」。

**现在什么情况**：四柱 v2 有条件放行、示意完整、履约仍裂。经办在数据工厂贴 URL，第一次成功仍脆（工人空态、配额、市场开关关闭时订不到）。买方看定价专业/企业档，**0 笔支付**。`/relay` 与旧「无渠道组屏」打架。市场总开关关闭。无租户访谈、无工单、Reach **未量化**。

**期望什么结果**：经办在空的非夹具企业里贴一条地址，要么在本企业结果里看到条数>0，要么立刻看到卡在工人或配额。买方能用支付宝或微信付中转 SKU 或套餐；付成才开通。访客看到的第一句仍是采集。

**凭什么说改善了**：判定窗内出现至少一家 **非夹具租户** 采集完成且条数>0。支付成功只作驱动指标。市场未量化，本轮是赌注，不得标通过。

#### FR-U33 支付成功才开通或续期对应套餐或中转额度

**可履约的支付成功** = FR-U38 验真通过的通道真通知（本笔待支付：商户、金额、订单号一致且视为通道侧真通知）。未验真或验真失败 **不得** 开通。验真通过且商品对应专业档 / 企业档 / 中转 SKU：该企业才开通或续期 **对应商品**——商品=`plan_pro` 只开通专业档，不得把中转 SKU 置 active。失败不得写成已买。跨企业支付不能开通本企业。支付已到账但开通未完成：租户看见「支付已到账，开通处理中」；套餐数字仍是开通前的。

| GWT | 类型 | 内容 |
|---|---|---|
| GWT-U33.1 | 正常 | **Given** 企业 A 待支付商品=`plan_pro`、中转 SKU 为 none、令牌数 0、GWT-U38.1 验真已通过 **When** 开通处理结束 **Then** A 的专业档为已开通；用量上限为该档数字；不得仍按免费档执法；中转 SKU 仍为 none；令牌数 0；不得按 GWT-U20.1 把「我的渠道组」判为已开通（走 GWT-U21.1） |
| GWT-U33.2 | 空态 | **Given** 企业 A 无任何已支付单据 **When** 管理员打开套餐页 **Then** 档位仍为开通前档；中转 SKU 未开通 |
| GWT-U33.3 | 越权 | **Given** 企业 B 一笔专业档支付成功（已验真） **When** 查看企业 A 套餐 **Then** A 档位不变；A 未获得 B 的开通 |

| GWT-U33.5 | 部分失败 | **Given** 通道真通知已验真通过、开通处理未完成 **When** 买方刷新套餐或中转页 **Then** 可见「支付已到账，开通处理中」；档位与 SKU 仍为开通前；不得显示已买完成 |
| GWT-U33.6 | 边界 | **Given** 同一笔待支付已被验真通过并开通一次 **When** 同一成功通知再次到达 **Then** 档位/SKU 只开通一次；不叠加上限 |

#### FR-U34 支付失败、取消、超时不得写成已买

| GWT | 类型 | 内容 |
|---|---|---|
| GWT-U34.1 | 正常 | **Given** 企业 A 待支付专业档 **When** 买方在通道侧取消并回到本站 **Then** 可见「支付未完成，套餐未开通」；档位不变；中转仍未开通 |
| GWT-U34.2 | 空态 | **Given** 待支付已超时未付 **When** 买方打开该单 **Then** 状态非已买；档位不变 |
| GWT-U34.3 | 越权 | **Given** 只读成员、企业 A 有一笔待支付 **When** 提交把该单标为已买 **Then** 拒绝；状态仍为未开通 |
| GWT-U34.4 | 非法流转 | **Given** 该单已是取消或超时 **When** 迟到的支付成功回调到达 **Then** 单据保持未开通；记下「迟到回调」；不开通套餐、不开通中转 |
| GWT-U34.5 | 边界 | **Given** 企业 A 待支付专业档、通道返回失败（非取消、非超时、非未配置） **When** 买方回到本站 **Then** 可见「支付未完成，套餐未开通」；档位不变；不是服务器错误页 |

#### FR-U35 专业/企业升级出口不是免费注册

免费档主按钮仍进企业注册（沿用 v2 GWT-05.1）。专业档主按钮进入结账且待支付商品=`plan_pro`。企业档主按钮进入结账且待支付商品=`plan_enterprise`（无独立 SKU 码 `plan_ent`，N/A）。未开通中转页「去升级」进入结账且待支付商品=`relay`。只读/经办点专业档主按钮或「去升级」→「请联系本企业管理员开通」，不创建待支付。**不得**进入同一注册表，**不得**再开一家免费企业。未登录先登录再回结账。文案仍受 FR-U24 约束。

| GWT | 类型 | 内容 |
|---|---|---|
| GWT-U35.1 | 正常 | **Given** 企业 A 买方已登录 **When** 点定价专业档主按钮 **Then** 进入结账；待支付商品=`plan_pro`；不到企业注册 |
| GWT-U35.2 | 空态 | **Given** 访客未登录 **When** 点定价专业档主按钮 **Then** 先到登录；登录后回到结账；不到「再注册一家」 |
| GWT-U35.3 | 越权 | **Given** 只读成员已登录 **When** 点专业档主按钮 **Then** 可见「请联系本企业管理员开通」；不到企业注册；不创建待支付 |
| GWT-U35.4 | 边界 | **Given** 访客打开定价 **When** 点免费档主按钮 **Then** 进入企业注册（与 v2 GWT-05.1 同一出口） |
| GWT-U35.5 | 正常 | **Given** 企业 A 买方已登录 **When** 点定价企业档主按钮 **Then** 进入结账；待支付商品=`plan_enterprise`；不到企业注册 |
| GWT-U35.6 | 出口 | **Given** 企业 A 中转 SKU 未开通、公司管理员（买方）已登录、当前页为「我的渠道组」且页上有「去升级」 **When** 点「去升级」 **Then** 进入结账；待支付商品=`relay`；不到企业注册 |
| GWT-U35.7 | 越权 | **Given** 企业 A 中转 SKU 未开通、当前页为「我的渠道组」且页上有「去升级」、登录者是只读或经办（非买方） **When** 点「去升级」 **Then** 可见「请联系本企业管理员开通」；不到结账；不创建待支付 |

#### FR-U36 非买方角色不能发起结账

买方 = 公司管理员或开通负责人。经办、只读、匿名不能创建待支付。超管无该企业空间时不能代付（本波无代付）。

| GWT | 类型 | 内容 |
|---|---|---|
| GWT-U36.1 | 正常 | **Given** 企业 A 公司管理员已登录、至少一通道已配置 **When** 进入结账 **Then** 能看到支付宝/微信选择（未配通道则走 FR-U32 空态句） |
| GWT-U36.2 | 空态 | **Given** 企业 A 经办已登录 **When** 点「去支付」 **Then** 可见「请联系本企业管理员开通」；不创建待支付 |
| GWT-U36.3 | 越权 | **Given** 匿名访客 **When** 直打结账 **Then** 不到改企业 A 档位；不创建待支付；无商户凭据 |
| GWT-U36.4 | 越权 | **Given** 平台超管已登录、无企业 A 空间、企业 A 有待开通商品 **When** 提交为企业 A 创建待支付或完成支付 **Then** 拒绝；不创建待支付；A 档位与 SKU 不变 |

#### FR-U37 埋点：支付成功与失败可查

支付成功是 **驱动指标**，不是北极星。查询面仅超管。`payment_succeeded` 在 FR-U38 验真通过后即可查，不必等开通完成（GWT-U37.7）。

| GWT-U37.1 | 正常 | **Given** GWT-U33.1 或 GWT-U33.4 已发生 **When** 超管按发生时间查询 **Then** 可查到 `payment_succeeded`，含 `tenant_id`、`channel`（`alipay` 或 `wechat`）、`product`（`plan_pro` / `plan_enterprise` / `relay`） |
| GWT-U37.2 | 空态 | **Given** GWT-U34.1 取消已发生 **When** 超管查询 **Then** 可查到 `payment_failed`，含 `reason=cancel`；**没有** 对应的 `payment_succeeded` |
| GWT-U37.3 | 越权 | **Given** 企业 A 买方已登录 **When** 寻找支付事实查询面 **Then** 与 GWT-U03.3 同一句 |
| GWT-U37.4 | 边界 | **Given** 待支付已超时未付（GWT-U34.2） **When** 超管查询 **Then** 可查到 `payment_failed`，含 `reason=timeout`；**没有** 对应的 `payment_succeeded` |
| GWT-U37.5 | 边界 | **Given** GWT-U34.5 通道失败已发生 **When** 超管查询 **Then** 可查到 `payment_failed`，含 `reason=channel_error`；档位未开通；**没有** 对应的 `payment_succeeded` |
| GWT-U37.6 | 空态 | **Given** GWT-U32.1 已发生 **When** 超管查询 **Then** 可查到 `payment_failed`，含 `reason=unconfigured`；单据为 unpaid；**没有** 对应的 `payment_succeeded` |
| GWT-U37.7 | 边界 | **Given** GWT-U33.5 已发生（验真已通过、开通处理未完成、单据为 paid_pending_fulfillment） **When** 超管按发生时间查询 **Then** 可查到 `payment_succeeded`（含 `tenant_id`、`channel`、`product`）；档位与 SKU 仍为开通前；不得因尚未开通而查不到该事件 |
| GWT-U37.8 | 空态 | **Given** GWT-U32.2 已发生 **When** 超管查询 **Then** 该次打开结账 **没有** `payment_failed`、**没有** `payment_succeeded`；无 `checkout_pending` 单据 |

#### FR-U38 [SEC-1] 通道通知验真后才履约

通道通知必须同时满足才视为可履约的真通知：与本笔待支付的 **订单号** 一致、与本通道已配 **商户** 一致、与该待支付单 **金额** 一致、且 **视为通道侧真通知**。任一不满足：保持未开通，档位与中转 SKU 不变，不得标已买，不得出现 `payment_succeeded`。伪造通知与金额/商户/订单号不符同等对待：不开通。本 FR **不选** 验真算法、不选密钥格式、不选回调路径。

| GWT | 类型 | 内容 |
|---|---|---|
| GWT-U38.1 | 正常 | **Given** 企业 A 一笔待支付（专业档、金额已写在该单、商户为已配支付宝商户）、通道侧真通知携带同一订单号、同一商户、同一金额 **When** 该通知到达并完成验真 **Then** 验真通过；随后可按 GWT-U33.1 开通 |
| GWT-U38.2 | 空态 | **Given** 企业 A 无任何待支付单 **When** 一条声称成功的通道通知到达 **Then** 不开通任何档位或 SKU；不创建已买单；无 `payment_succeeded` |
| GWT-U38.3 | 越权 | **Given** 企业 A 一笔待支付仍未开通 **When** 一条缺通道签名的成功报文到达（订单号可与该单相同；本句不规定签名算法） **Then** 保持未开通；档位/SKU 不变；无 `payment_succeeded` |
| GWT-U38.4 | 边界 | **Given** 企业 A 待支付金额为该单所写金额 **When** 通道通知到达但金额与该单不符 **Then** 保持未开通；档位/SKU 不变；无 `payment_succeeded` |
| GWT-U38.5 | 边界 | **Given** 企业 A 待支付绑定已配支付宝商户 **When** 通道通知到达但商户与该单或已配商户不符 **Then** 保持未开通；档位/SKU 不变；无 `payment_succeeded` |
| GWT-U38.6 | 边界 | **Given** 企业 A 待支付有明确订单号 **When** 通道通知到达但订单号与该单不符 **Then** 保持未开通；档位/SKU 不变；无 `payment_succeeded` |

## 3.1 状态流转

### 采集任务（本波加深）

```
（无工人/配额已尽）──提交──> 不入队或 3 秒内失败可见
pending ──工人执行──> running ──抽到条──> completed（条数>0）
running ──抽到 0 条──> completed（0 条）或 failed
running ──120 秒无终态──> 用户可见工人不在线，不得无限「运行中」无解释
```

**非法：** 无工人却超过 3 秒仍「正在采集」；结果写入其它企业；候选当合格出数。

### 中转 SKU

```
none ──支付成功且商品含中转──> active
active ──到期或停用──> expired
expired ──续费支付成功──> active
none ──支付失败/取消/超时──> none
```

终态：无（可续费）。

| 流转 | 触发 | 谁 | 副作用 |
|---|---|---|---|
| none → active | FR-U38 验真通过且商品含中转，开通完成 | 系统 | 可打开「我的渠道组」；可签发令牌 |
| active → expired | 到期巡检或运营停用 | 系统 / 超管 | 不能签发新令牌；已签发令牌不可再用 |
| expired → active | 续费且 FR-U38 验真通过，开通完成 | 系统 | 恢复签发 |

**非法流转：**

| 非法 | 期望（状态 / 记录 / 副作用） |
|---|---|
| 未支付 none → active | 保持 none；无令牌 |
| 商品=`plan_pro` 支付成功 → 中转 SKU active | 专业档可开通；中转保持 none；令牌数 0；不得走 GWT-U20.1 |
| 伪造或金额/商户/订单号不符的成功通知 → active | 保持 none；不履约；无 `payment_succeeded` |
| expired 下签发令牌 | 拒绝；无新令牌；文案「中转已到期」 |
| expired 下使用到期前旧令牌 | 失败；不得当有效凭证 |
| 已开通后经办签发令牌 | 拒绝；令牌数不变 |
| 租户自助把 SKU 标为 active | 拒绝；状态不变 |
| 企业 B 的支付开通企业 A | A 保持原状态 |
| 超管代企业支付 | 拒绝；不创建待支付；档位/SKU 不变 |

### 支付单据

```
checkout_pending ──FR-U38 验真通过且开通完成──> fulfilled
checkout_pending ──用户取消 / 超时 / 通道失败 / 未配置──> unpaid
checkout_pending ──验真通过但开通未完成──> paid_pending_fulfillment ──开通完成──> fulfilled
checkout_pending ──伪造或金额/商户/订单号不符──> checkout_pending（不得 fulfilled）
```

选择未配置通道并去支付（GWT-U32.1）走「未配置」边：先 `checkout_pending` 再 `unpaid`，并记 `payment_failed`（`reason=unconfigured`）。仅打开结账（GWT-U32.2）不进入该边、不创建 `checkout_pending`。验真通过、开通未完成时 `payment_succeeded` 已可查（GWT-U37.7），单据为 `paid_pending_fulfillment`。

终态：`fulfilled`、`unpaid`。

**非法流转：**

| 非法 | 期望 |
|---|---|
| unpaid → fulfilled（迟到成功回调） | 保持 unpaid；记「迟到回调」；不履约 |
| 伪造或金额/商户/订单号不符 → fulfilled | 保持 checkout_pending 或 unpaid；不履约；无 `payment_succeeded` |
| fulfilled → unpaid | 保持 fulfilled；档位/SKU 不回滚（退款本波不做） |
| 第二次成功回调再加一份上限 | 只开通一次 |
| 只读把单据标 fulfilled | 拒绝；状态不变 |
| 超管代付标 fulfilled | 拒绝；状态不变 |

此表须与日后 `/dba` 的 db-spec 2.1 一致。不一致以本文为准，但要显式同步。本文件 **不选表名**。

### 市场总开关 / 安装行

沿用 v2 §3.1 上架与安装行。本波追加：总开关关闭时 **不得** 新产生安装行（FR-U11）。
