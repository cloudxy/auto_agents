## US-N1-01 空的非夹具租户第一次出数

### Card

作为任务数为 0 的非夹具企业里的采集经办，我想粘贴一条地址后在本企业「我的结果」看到条数>0，以便当天能交差——而不是只在夹具企业里演示过一次。

### Context

| 项 | 内容 |
|---|---|
| 什么时候用 | 新企业第一次采集 |
| 多频繁 | 每企至少一次；之后按任务 |
| 这之前 | 免费注册并登录；配额未尽 |
| 这之后 | 导出 CSV/JSON，或发现被工人/配额拦住（US-N1-02） |
| 现在怎么做 | QC 夹具曾出数后删除；本机任务数 0；经办贴 URL 走 generic / example，第一次成功仍脆 |
| 不做会怎样 | 北极星分母永远是夹具；赌注无法证伪 |

### Confirmation

FR-U01、FR-U03。夹具地址沿用 v2：`example` + `https://httpbin.org/get` + 120 秒。点提交后 3 秒内见已入队（NFR-U01）。企业必须不在内部测试名单。企业 B 看不到 A 的条。D3 拦住 vs 完成见 GWT-U03.4 / U03.5。

## US-N1-02 卡住时不假装在爬

### Card

作为采集经办，我想在工人不在线或配额已尽时立刻看到「采集未运行」或「已达配额上限」和下一步，以便去找值班或清理结果——不要「正在采集」一直转。

### Context

| 项 | 内容 |
|---|---|
| 什么时候用 | 每次提交；工人掉线；存储/token 满 |
| 多频繁 | 空租户第一次特别疼 |
| 这之前 | 已登录，准备贴 URL |
| 这之后 | 存储满 → 去结果库；只读/经办点「申请提升」→ 联系本企业管理员；买方点「申请提升」→ 结账（US-N3-02）。都不到再注册 |
| 现在怎么做 | 工人空态、配额页曾泄漏内部码 |
| 不做会怎样 | 出数环看起来在爬，北极星永远 pending |

### Confirmation

FR-U02。工人句与配额句不得混用。禁止 `QUOTA_EXCEEDED` / 裸 `429`。将满 ≥90% 且未满是单独一档（GWT-U02.5）。只读不能提交。拦住句 **3 秒内**可见（NFR-U01）。「申请提升」：只读/经办 → 联系本企业管理员（GWT-U02.6）；买方 → 结账（GWT-U02.7）。v2 GWT-12.6「本波不必支付」对本特征作废。

## US-N3-01 已开通才用「我的渠道组」

### Card

作为已开通中转 SKU 的本企业管理员，我想打开「我的渠道组」看本企业用量并签发令牌（明文只出现一次），以便把中转当产品用——未开通时不能装成已买，也不能改全局熔断。

### Context

| 项 | 内容 |
|---|---|
| 什么时候用 | 支付开通之后；到期后不能签发 |
| 这之前 | 买方付完中转 SKU（US-N3-02） |
| 这之后 | 经办在平台路径继续走网关；浏览器仍不能直连平台网关 |
| 现在怎么做 | `/relay` 与旧 GWT-60.1「无渠道组屏」互否；CONTEXT 曾写令牌不发给租户 |
| 不做会怎样 | Q-RELAY 已答却无可判定产品面 |

### Confirmation

FR-U20、FR-U21、FR-U22、FR-U23。打开「我的渠道组」≠ 直打平台值班页（v2 GWT-07.3/14.3 已在 spec §0 作废其合并句）。企业 B 看不到 A。到期文案「中转已到期」。已开通后经办不能签发。到期后旧令牌不可再用。专业档开通（GWT-U33.1）不得当中转已开通：SKU 仍 none、令牌数 0、不能走 GWT-U20.1。未开通页买方点「去升级」→ 结账商品=`relay`（GWT-U35.6）；只读/经办同一 CTA → 联系管理员、不创建待支付（GWT-U35.7）。吊销后打开页见「还没有令牌」（GWT-U23.2）；用已吊销令牌失败（GWT-U23.8）。

## US-N3-02 付成才开通

### Card

作为开通企业的买方，我想用支付宝或微信支付专业档、企业档或中转 SKU，以便付成才开通、取消则不开——不要再被送去免费注册。

### Context

| 项 | 内容 |
|---|---|
| 什么时候用 | 点定价专业/企业主按钮；或从「未开通中转」去升级 |
| 多频繁 | 每企少次 |
| 这之前 | 已登录为公司管理员或开通负责人 |
| 这之后 | 档位或 SKU 变为已开通；或看到未完成句 |
| 现在怎么做 | 0 笔支付；专业/企业曾进同一注册 |
| 不做会怎样 | 履约出口仍裂；但仍不得写「当前可买」（US-N3-03） |

### Confirmation

FR-U30…U38。通道闭集支付宝+微信。未配通道：「收款通道未开通」或「该通道未开通」，不是服务器错误页。选择未配置通道并去支付：先 `checkout_pending` 再 `unpaid` + `payment_failed` `unconfigured`（GWT-U32.1）；仅打开结账不建单（GWT-U32.2）。经办/只读不能结账。超管不能代付。迟到成功回调不履约。**通道通知须验真**（商户+金额+订单号一致且视为通道侧真通知）否则不开通；缺通道签名的成功报文不开通（GWT-U38.3）；金额/商户/订单号不符均不开通（FR-U38 [SEC-1]）。专业档主按钮待支付商品=`plan_pro`（GWT-U35.1）；企业档主按钮待支付商品=`plan_enterprise`（GWT-U35.5；无独立 `plan_ent`，N/A）；未开通中转「去升级」待支付商品=`relay`（GWT-U35.6）；只读/经办同一 CTA 不创建待支付（GWT-U35.7）。专业档开通后中转仍 none、令牌数 0、不能走 U20.1（GWT-U33.1）。`payment_succeeded` 可在验真后、开通前查到（GWT-U37.7）。支付成功是驱动指标，不是北极星。

## US-N3-03 可见面不得写「当前可买」

### Card

作为访客或租户成员，我在 Q-AGPL 未答之前不应在任何对我可见的面上读到「当前可买」，以便不被写成已经能买中转——即使后台已经能收款。

### Context

| 项 | 内容 |
|---|---|
| 什么时候用 | 打开任一访客或租户可见面（含首页 / 功能介绍 / 定价 / 后台 / 结账 / 我的渠道组） |
| 现在怎么做 | Q-PRICE=履约，但绑定句仍要 Q-AGPL |
| 不做会怎样 | A2 复活：口头可买=当前可买 |

### Confirmation

FR-U24、FR-U35。禁区 = **所有访客/租户可见面**，不限三页。免费档仍去注册。专业/企业去结账。公司管理员不能改定价文案。
