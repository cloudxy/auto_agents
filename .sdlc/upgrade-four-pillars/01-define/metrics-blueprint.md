# 度量蓝图 · 四柱深度调整（upgrade-four-pillars）

> 泳道：L3｜作者：pm 帽｜日期：2026-09-12｜对应 `spec.md` v1.2（§6 不另给表）
> **本文件是 analyst 复盘的唯一口径。** spec §6 已删除竞争表，只保留指针。北极星/驱动/护栏以本文为准。冲突以本文为准。
> 前合同：`feat-four-pillars-v2/01-define/metrics-blueprint.md` 的 WACT 仍是 v2 合同指标。**本特征北极星**按 briefing 赌注改写为非夹具合格出数，**不是**把支付成功或订阅成功升成北极星。
> 约束：ops **0 工单**、无生产 n、Reach **未量化**。禁止写转化率提升百分比。禁止标 falsify 通过。本轮成功 = 能判定。
> 数仓分层 / 离线模型：**实现面 N/A**。四周数字从产品事实查询面出。

## 1. 判定纪律

| 项 | 规则 |
|---|---|
| 判定周期 | 所在波对用户可用之后 **4 个上海自然周**；中途不下成败 |
| 基线 | 无。第一轮目标就是建立基线 |
| 时区 | **Asia/Shanghai 业务日**；指标用 **事件发生时间**（不是入库记录时间） |
| 分流 | 无 A/B。市场总开关是发布控制。若将来做实验，分流单位 = **企业** |
| 排除 | 市场候选不得计入北极星。内部测试企业用超管维护的夹具名单（`is_internal_fixture=true`），不得假装已有自动过滤器却不验收字段 |
| 验收 | 以事件可查为准。不得用官网 Hero 数字、后台任务总数冒充北极星 |
| 禁止当 OEC | Hero 静态数字、全历史成功率、技能均分、listed 资产数、扫描成功次数、渠道 24h、支付成功率当北极星 |
| Q-VOICE | **已答采集**。禁止把核心动作改为订阅成功或支付成功。禁止双北极星 |

Hero 示意大数 **禁止当基线**。

## 2. 北极星（唯一）

| 字段 | 内容 |
|---|---|
| 名称 | 非夹具租户合格出数（企业去重） |
| 口径 | 一个判定窗内，至少发生 1 次核心动作的 **非夹具企业** 去重数 |
| 核心动作 | `task_completed` 且 `result_count>0` 且 `is_marketplace_candidate=false` 且 `is_internal_fixture=false` |
| 来源 | 事件 `task_completed`（FR-U03：`tenant_id`、`result_count`、`spider`、`source`、两布尔） |
| 时间窗 | 上海周一 00:00 至周日 24:00，事件发生时间；四周复盘把四周每周都报出 |
| 目标值 | 建立基线。四周结束必须能报「这四周每周该数=？」；报不出 = FR-U03 失败。不设提升百分比 |

选这个：briefing 赌注 + Q-VOICE=采集。经办价值是本企业表里有条。支付成功是套餐出口，离第一次交差更远，只进驱动。

混淆：该数=0 可能是没人来 / 没登录 / **工人未运行** / 配额拦住。用 D3 拆开，不得把工人空洞解释成「没人要采集」。

v2 WACT（周活跃完成租户，含夹具口径差异）**不是**本蓝图北极星。不要并列两个北极星。

## 3. 驱动指标（4 个）

支付成功在本层。**不抢北极星。**

### D1 非夹具成功支付企业数

| 字段 | 内容 |
|---|---|
| 口径 | 分子：一周内至少一次 `payment_succeeded` 的非夹具企业去重。分母：无（报去重企业数，不报转化率——Reach 未量化） |
| 来源 | FR-U37；字段 `tenant_id`、`channel`（`alipay`/`wechat`）、`product`（`plan_pro`/`plan_enterprise`/`relay`） |
| 时间窗 | 上海自然周，事件发生时间 |
| 目标 | N3 对用户可用后建基线 |
| 诊断 | 北极星>0 且 D1=0 → 采集赌注可活、收款未发生（允许；不因此改北极星）。D1>0 且北极星=0 → 买方付了但经办未交差 |

### D2 订一行企业数

| 字段 | 内容 |
|---|---|
| 口径 | 一周内至少一次 `market_subscribe_succeeded` 的非夹具企业去重 |
| 来源 | FR-U14（事件名沿用 v2 `market_subscribe_succeeded`） |
| 时间窗 | 上海自然周，事件发生时间 |
| 目标 | 市场总开关打开后建基线。开关关闭时该数必须为 0，**不得**解释成「没人要订」 |
| 诊断 | 列表浏览有、订阅 0：查开关、预告占比、只读角色、许可闸 |

### D3 空租户首次提交拦住率

| 字段 | 内容 |
|---|---|
| 口径 | 分子：非夹具企业 **第一次**提交采集被工人不在线或配额已尽拦住的企业数。分母：非夹具企业第一次提交采集的企业数 |
| 来源 | FR-U03 GWT-U03.4 / U03.5 须能区分拦住 vs `task_completed`；提交侧沿用 v2 `task_run_submitted`（若查询面没有该事件则本指标 ⚠️ 不可测，改用四周访谈 5 个空租户路径，不得假装能测） |
| 时间窗 | 每企从首次提交起算；周报按事件发生时间归周 |
| 目标 | 建基线 |
| 诊断 | 分母有、北极星=0、D3 高 → 工人/配额，不是获客句失败 |

### D4 中转 SKU 开通企业数

| 字段 | 内容 |
|---|---|
| 口径 | 一周内 `payment_succeeded` 且 `product=relay` 且开通完成（SKU none→active）的非夹具企业去重 |
| 来源 | FR-U37；开通未完成的 `paid_pending_fulfillment` **不进**分子 |
| 时间窗 | 上海自然周，事件发生时间 |
| 目标 | 建基线 |
| 诊断 | D1 含 relay 意图但 D4=0 → 履约断裂（GWT-U33.5） |

## 5. 埋点契约（本特征新增/加深）

字段最低集：`occurred_at`、已登录则 `tenant_id`/`user_id`/`role`。切日：存 UTC、报表日 Asia/Shanghai。失败上报不挡主路径。查询面 **仅平台超管**。租户无查询面（GWT-U03.3 同一句）。

v2 已冻、本波继续用的事件：`task_run_submitted`、`task_completed`、`quota_exceeded`（内部事件名可以保留；**用户可见文案**仍禁该码）、`market_subscribe_succeeded`、`market_subscribe_rejected`。

本波必须可查的增量：

| 事件 | 何时 | 关键字段 | 对应 FR | 查询面 GWT |
|---|---|---|---|---|
| `task_completed` | 任务完成 | 增加 `is_internal_fixture`（布尔）；保留 `result_count`、`is_marketplace_candidate` | FR-U03 | GWT-U03.1 / U03.2；拦住 vs 完成 GWT-U03.4 / U03.5 |
| `payment_succeeded` | 通道真通知验真通过且可关联企业（FR-U38）；**可在开通完成前查到**（GWT-U33.5 / GWT-U37.7）。开通完成不是该事件的前置 | `tenant_id`、`channel`=`alipay`\|`wechat`、`product`=`plan_pro`\|`plan_enterprise`\|`relay` | FR-U37 | GWT-U37.1（开通后仍可查）；GWT-U37.7（验真后、开通前）；伪造/金额不符/商户不符/缺通道签名无此事件（GWT-U38.3–U38.5） |
| `payment_failed` | 取消/超时/通道失败/未配置 | `reason`=`cancel`\|`timeout`\|`channel_error`\|`unconfigured`；能消歧则带 `tenant_id` | FR-U37 | GWT-U37.2 / U37.4 / U37.5 / U37.6 |
| `market_subscribe_succeeded` | 开关打开后订一行成功 | `host`、`tenant_id` | FR-U14 | GWT-U14.1 |

通知类型字符串 **禁止**当本蓝图事件。

## 7. 漏斗

### F1 激活（官网 → 第一次非夹具合格出数）

步骤：曝光（第一句=采集）→ 免费注册 → 首次登录 → 首次提交 → 首次非夹具合格出数。

- 不允许把「体验 AI 采集流程」算进 F1 分母（沿用 v2）。
- 不允许把夹具企业算进分子。
- 工人拦住留在 D3，不把分母里的人从 F1 删掉。
- 步间 168h。回退再前进：按企业取首次到达该步的时间。

### F 支付（驱动，不是北极星）

步骤：点专业/企业主按钮或未开通中转「去升级」 → 进入结账（不到注册；商品分别为 `plan_pro` / `plan_enterprise` / `relay`；无独立 `plan_ent`，N/A）→ 选支付宝或微信 → `payment_succeeded`（验真后即可查，不必等开通）→ 开通完成。

取消/超时/通道失败/未配置进 `payment_failed`（`reason` 闭集），不进成功分子。伪造或金额/商户/订单号不符 **不得** 进 `payment_succeeded`。Q-AGPL 未答期间，本漏斗 **不得**在任何访客/租户可见面写成「当前可买转化」。

### F 市场

步骤：总开关打开 → list → detail → subscribe_succeeded。开关关闭时本漏斗不可发生，报「未开放」而不是转化 0%。
