**本票做什么**：没有在线采集工人时阻止提交或立即可见「采集未运行，不会出数」（`SPIDER_WORKER_OFFLINE`）。夹具出数：爬虫名 `example`；地址 `https://httpbin.org/get`；等待上限 120 秒。零条目必须离开「运行中」。IdleAutoClose 产品窗 ≠ 21600（21600 是渠道探针锁）。compose 无工人 = 空态（`run.py all` 已 spawn Worker 的故事过期；根 compose 仍无工人）。

**本票不做什么**：不承诺任意站点/登录墙/代理网；不把 Worker 焊进根 compose；不把 21600 当收尾窗口。

## GWT / Then（不得改写成短句）

- GWT-18.1：至少一名采集工人在线，企业 A 经办用爬虫 `example` 提交地址 `https://httpbin.org/get`，等待采集结束（上限 120 秒）→ 120 秒内任务进入完成且条数>0；结果在 A 的「我的结果」；可按 FR-03 导出。
- GWT-18.2：没有在线工人，经办点提交 → 提交被拦住或立即看到「采集未运行，不会出数」；任务不得长时间停在等待且看起来像正在爬。
- GWT-18.3：只读成员点提交 → 拒绝；不入队。
- GWT-18.4：工人在提交后掉线，任务无终态已满 120 秒 → 用户能在任务/节点上看到工人不在线，而不是无限「运行中」无解释。
- GWT-19.1：工人在线但选择器未抽到任何条，采集结束 → 任务离开「运行中」，进入完成（0 条）或失败；页面能看到 0 条。
- GWT-19.2：任务 0 条已收尾，打开任务不是空白表无说明；能区分「真的 0 条」与「还在跑」。
- GWT-19.3：企业 B 打开企业 A 的 0 条任务，与不存在同形。
